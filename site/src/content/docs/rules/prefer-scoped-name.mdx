This rule enforces that package names use a specific scope or one from a set of allowed scopes.
It is opt-in and does not belong to the recommended configuration.

Provide a `preferred` scope, an `allowed` list, or both.
With no options, the rule does nothing.

## Examples

Given the following configuration:

```js
// eslint.config.js
export default [
  {
    rules: {
      'package-json/prefer-scoped-name': [
        'error',
        { preferred: '@company', allowed: ['@partner'] },
      ],
    },
  },
];
```

## Options

{/* begin auto-generated rule options list */}

| Name        | Description                                        | Type     |
| :---------- | :------------------------------------------------- | :------- |
| `allowed`   | Additional permitted scopes, each starting with @. | String[] |
| `preferred` | The scope to suggest or fix for private packages.  | String   |

{/* end auto-generated rule options list */}

### `preferred`

When configured, packages without the preferred scope are reported.
Scopes defined here should always include a `@` prefix.
For private packages (`"private": true`), `--fix` can rename the package.
For public packages, an editor suggestion is offered instead, since automatically renaming a published package could result in a breaking change.

### `allowed`

Other scopes that are accepted without a warning. When only `allowed` is configured, unscoped names are accepted, but unexpected scopes are reported without an automatic replacement.
Scopes defined here should always include a `@` prefix.

## When Not to Use It

If packages in your project intentionally use unrelated scopes, disable the rule or list all permitted scopes.
